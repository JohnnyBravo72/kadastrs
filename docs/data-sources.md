**Checked:** 2026-10-09, against the data.gov.lv CKAN API (`https://data.gov.lv/dati/api/3/action/`).
**How:** [`etl/discovery/ckan_discover.py`](../etl/discovery/ckan_discover.py), which can be re-run. It uses only metadata, DataStore column names, aggregate SQL counts, zip directory listings and three small files: the cadastre XSD schemas (23 KB), one 3.5 MB cadastre SHP zip (CRS only) and CSV header bytes. No bulk downloads, and no data rows with personal data were fetched.
**Every resource with its URL, format, host and size:** [data-sources-resources.md](data-sources-resources.md) (generated by the script).
**Samples (Phase 0 step 2):** 2026-10-09, taken for **Jelgava (ATVK 0003000)**. The pilot area is Jelgava, Jūrmala and Daugavpils (§2a).
- Downloaded by [`etl/discovery/samples.py`](../etl/discovery/samples.py) into `data/samples/` (not committed; `data/samples/manifest.json` has URL, size and SHA-256 per file).
- Inspected by [`etl/discovery/inspect_samples.py`](../etl/discovery/inspect_samples.py) (`shp`, `xml`, `csv`, `bisrule`, `flood`, `gaps`; project venv with pyshp, shapely and pyproj 3.8 / PROJ 9.8.1).
- Pilot choice by [`etl/discovery/pilot_flood.py`](../etl/discovery/pilot_flood.py).
- Each source below has a **Sample inspection** part.

Status words used below:
- **FOUND**: dataset located, metadata read, and the answer comes from data.gov.lv content.
- **PARTIAL**: found, but it does not fully cover what PLAN.md needs.
- **UNCLEAR**: something exists, but the key point could not be confirmed. The note says what was tried.
- **NOT FOUND**: searched and absent. The searches are listed.

"Field names" below come from the CKAN DataStore (`datastore_search`, `limit=0`) unless another source is given. Fill rates come from `datastore_search_sql` counts.

## 2. Findings that change PLAN.md

1. **CRS.** VZD moved its data to **LKS-2020 TM**.
   - The VARIS change log says "07.10.2026 – transformētas koordinātas no LKS-92 TM uz LKS-2020 TM".
   - The cadastre map description says LKS-2020 TM, and the `.prj` in a cadastre SHP zip (Ventspils) reads `PROJCS[LKS_2020_Latvia_TM … AUTHORITY[EPSG,10306]]`.
   - DAP nature data says LKS-92 in its descriptions.
   - The TAPIS WFS advertises `EPSG:3059`.

   **Decided as D9 (2026-10-09):** store in EPSG:10306 and transform 3059 sources on import with EPSG:10838. This needs PROJ ≥ 9.8 and the grid file; see `docs/decisions.md`.
2. **PLAN's dataset names are partly wrong.**
   - `valsts-adresu-registra-informacijas-sistemas-atvertie-dati` exists but returns *403 Authorization Error* (private or deleted). The live VARIS dataset is `varis-atvertie-dati`.
   - `pldu-riska-karu-atvrtie-dati-un-servisi5` is **"Jūras vēja uzplūdi reizi 200 gados WMTS"**, not the spring 10-year flood.
   - `kadastra-informacijas-sistemas-atvertie-dati` is the *text* data. The spatial data is a separate dataset.
3. **Sanctions data is on data.gov.lv** (UR and FID). PLAN §2.3/§6 assumed it was not. It holds personal data, so under the open-data policy (D6, decided) only legal entities matched by reg. no. are used, and natural-person fields are not imported.
4. **Owners differ from PLAN:** cultural heritage is published by KISC (Kultūras informācijas sistēmu centrs); municipal liabilities by Valsts kase.
5. **Don't import from the DataStore copies; import the raw files.**
   - Several DataStore tables type designations as `numeric`, which drops leading zeros: BIS `Buves_kadastra_apzimejums`, and EU 14–20 and RRF `KadastraNumurs`.
   - The BIS case-objects DataStore table has exactly 48,000 rows; **the CSV has 425,185 rows** (confirmed in step 2). The DataStore copy is truncated.
6. **Hosted outside data.gov.lv (D1 matters):**
   - de minimis (`deminimis.fm.gov.lv`);
   - IUB procurement JSON (`open.iub.gov.lv`);
   - DAP ArcGIS REST (`ozols.gov.lv`, alongside SHP that is on data.gov.lv);
   - all flood and TAPIS services (`geo-dpps.viss.gov.lv` proxying `geodata.lvgmc.lv`, `geoserver.lvgmc.lv`, `tapis.gov.lv`);
   - flood SHP files, which are only reachable through geolatvija.lv product pages.
7. **TLS:** Python's default CA store fails on `deminimis.fm.gov.lv` and `open.iub.gov.lv` (*CERTIFICATE_VERIFY_FAILED, unable to get local issuer certificate*). `curl` with the Windows store connects (HTTP 200). The ETL needs a proper CA bundle; verification must not be switched off.
8. **Personal data in sources** (must not be stored, per CLAUDE.md):
   - de minimis: `person_title` "vārds un uzvārds" and `person_reg_nr` "personas kods";
   - UR `sanctions`: `name`, `birth_date`;
   - EU project lists: recipient e-mail `FinansejumaSanemejaEpasts`.

   Import only the needed columns.

## 2b. Reference: CSBLatvia/postgresql-open-data-lv (Phase 0 step 7)

**What:** [github.com/CSBLatvia/postgresql-open-data-lv](https://github.com/CSBLatvia/postgresql-open-data-lv), scripts used by the Central Statistical Bureau to import Latvian open data into PostgreSQL/PostGIS with history.

**Read 2026-10-09 as a structural reference only.**
- The GitHub API shows **no licence** (`license: null`); last push 2026-10-09. **No code was copied into this repo.**
- Files read: `README.md` and the `vzd/` scripts for VARIS, the cadastre map, the cadastre text data and pre-registered buildings.

**Structure**
- One schema per agency (`vzd`, `lad`, `mvr`, `csp`). Raw files land in staging tables (the VARIS CSV via `COPY`, SHP/XLSX via the OGR foreign data wrapper) and are then normalised into history tables.
- **History per object:** every table has `date_created` / `date_deleted`. A changed object (geometry, parcel link or object code) closes the old row and inserts a new one. Classifier texts (property kind, ownership status, …) go into lookup tables.
- Geometry is `MultiPolygon` / `Point` in **SRID 10306**: they also moved to LKS-2020, and their README requires PROJ ≥ 9.6.1. Every geometry has a GIST index.

**Import order (their README):**
1. roles, database and extensions;
2. administrative territories and villages (`aw_shp`);
3. VARIS CSV (`aw_csv`) + deleted-address coordinates (`aw_del`);
4. cadastre map (`kk_shp`) + pre-registered buildings;
5. cadastre text (`nivkis_txt`: property, ownership, parcel, parcel part, building, premise group, address, encumbrance, mark, valuation);
6. derived tables (current buildings with geometry and address).

VARIS runs daily on workdays via cron; the cadastre runs weekly. **Resource URLs are read from the dataset's `.jsonld` (`dcat:accessURL`) on every run**, the same idea as our "take URLs from `package_show`" rule.

**Pitfalls they handle that our plan does not yet cover:**
1. **Geometry normalisation:** they repair geometries, explode them, **keep only polygon parts** (repair can produce lines or points), **union the parts per code**, and store them as MultiPolygon. Our plan only says `make_valid`, so add the polygon-only filter and the union per code (per `CODE` + `PARCELCODE` for servitudes). In the Jelgava sample, codes are unique for parcels, buildings and parcel parts, but 57 parcels and 3 buildings are multi-ring.
2. **Dirty text in cadastre XML:** they remove carriage returns, tabs and backslashes from building, premise-group and property texts. Our ElementTree parsing is unaffected, but **normalise whitespace in text fields** before Excel export.
3. **VARIS CSV quotes:** values contain doubled quotes (e.g. `"""4"""`, `"Elektriķi 2"`). OGR FDW drops them, so they use `COPY … QUOTE '"' ESCAPE '"'`. We must use a real CSV parser (Python `csv` does this correctly) and never split on commas.
4. **Object kind by `OBJECTCODE`:** they separate buildings from engineering structures with `OBJECTCODE < 6000000000`. In our sample the first digit is 5 = building, 6 = engineering structure, 7 = parcel, parcel part or servitude.
5. **History dates:** they use the run date (minus 1 day), which needs manual fixes. **We keep the source's `last_modified` as the version date** (PLAN §2.2).
6. **Storage:** per-object diffs are much smaller than full snapshots. Our full `dataset_version` snapshots are simpler and fine for the pilot area; revisit for whole-country scale (Phase 9).

**Two more VZD open datasets they use** (both on data.gov.lv, CC-BY-4.0; metadata checked via `ckan_discover.py show`):
- **[`pirmsregistretas-buves`](https://data.gov.lv/dati/lv/dataset/pirmsregistretas-buves)** (quarterly, CSV/XLSX): pre-registered buildings with building designation, parcel designation, address, floors, built-up area, wall material and registration date. **No geometry.**
  - **Sample checked** (`20260803_pirmreg_buves.csv`, 16.9 MB, 87,872 rows, data date 2026-08-03; UTF-8 with BOM although its metadata says ISO-8859-1; the metadata also lists a column `JnBuiDateFrom` that the file calls `BuiRegDate`).
  - **6,996 rows have lost a leading zero** in VZD's own file (`BuiCadNr` 13 instead of 14 digits, `ParCadNr` 10 instead of 11), so zero-padding is required (PLAN §2.5 E2).
  - **Small value for the no-geometry fallback:**
    - Jelgava's cadastre text marks 3,328 buildings as pre-registered; this dataset has 1,225 of them, and where both exist the parcel agrees with the cadastre link in 1,224 of 1,224.
    - Of the **2,072** pre-registered Jelgava buildings without geometry, **all 2,072 already have their parcel link in `building.xml`**, and only **18** are in this dataset.
    - **The cadastre text is the source for the fallback.** This dataset is at most a cross-check. Earlier text here overstated its role.
  - **Decided 2026-10-09:** recorded as a **secondary cross-check outside the MVP** (PLAN §2.3) for the Jelgava reasons above. Its value is re-checked on whole-country data in Phase 9.
- **[`dzesto-adresu-koordinatas`](https://data.gov.lv/dati/lv/dataset/dzesto-adresu-koordinatas)** (annual, CSV/XLSX): code, end date, X/Y coordinates and full text of **deleted addresses**. For a `DEL` address without a `KODS_HIS` link (about 97%), the point could locate the parcel or building there now and suggest a "probable" current address. Not yet in PLAN; a candidate for Phase 3. The coordinate CRS was not checked.

Not relevant here: their LAD (field blocks), forest register, NĪTIS (market transactions) and postal-code Voronoi scripts.

## 3. Per source

### 3.1 Address Register (VARIS)
- **Dataset:** [`varis-atvertie-dati`](https://data.gov.lv/dati/lv/dataset/varis-atvertie-dati), id `6b06a7e8-dedf-4705-a47b-2a7c51177473`. Publisher VZD, daily, CC-BY-4.0, metadata modified 2026-10-09.
- **Resources (41, all on data.gov.lv):**
  - CSVs: cities, municipalities, parishes, villages, streets, building/parcel addresses (`aw_eka.csv`, 142 MB), premise-group addresses, history tables, Riga suburb links, place centroids, document metadata. Each has a JSON metadata file.
  - `aw_shp.zip` (52.6 MB), with layers `Adm_rob, Autoceli, Ciemi, Ekas, Ielas, Mazciemi, Novadi, Pagasti, Pilsetas`.
- **Key fields** (`aw_eka`): `KODS, TIPS_CD, STATUSS, VKUR_CD, VKUR_TIPS, NOSAUKUMS, SORT_NOS, ATRIB, PNOD_CD, DAT_SAK, DAT_MOD, DAT_BEIG, FOR_BUILD, PLAN_ADR, STD, KOORD_X, KOORD_Y, DD_N, DD_E`.
- **CRS:** LKS-2020 TM since 2026-10-07 (from the description; the `.prj` inside `aw_shp.zip` was not read).
- **Note:** PLAN's slug returns 403. The full field specification is linked from the description on vzd.gov.lv (not read; outside data.gov.lv).

**Sample inspection (national files)**
- `aw_eka.csv` (141.7 MB):
  - UTF-8 **with BOM**, CRLF, comma-delimited, 610,914 rows, columns as above.
  - `KODS` and `VKUR_CD` are always 9 digits with no leading zeros.
- `aw_shp.zip` (52.6 MB):
  - `.cpg` UTF-8, no encoding errors.
  - **The `.prj` is named `LKS-2020_Latvia_TM_EPSG_10306` but has no `AUTHORITY` clause**, so the ETL must assign SRID 10306 explicitly and not trust auto-detection.
  - `Ekas.shp` holds 550,686 address points, `KODS` unique, 0 invalid. `Adm_rob` 628, `Novadi` 35, `Pilsetas` 82 polygons, all valid.
  - The DBF types `KODS` as numeric `N(10)`. Harmless for 9-digit codes, but read it as text (CLAUDE.md rule 8).
- **CSV vs SHP count gap, explained:**
  - The CSV has 610,914 rows (`STATUSS`: `EKS` 550,685, `DEL` 32,453, `ERR` 27,776); the SHP has 550,686 points (all `EKS` plus 1 `DEL`). Every SHP code is in the CSV.
  - The 60,228 CSV rows missing from the SHP are **all `DEL` (32,452) or `ERR` (27,776)**, and **none has coordinates** (`KOORD_X` empty). 32,787 of them have `DAT_BEIG` set.
- **Meaning of `STATUSS` (confirmed):** **EKS – eksistējošs; DEL – likvidēts; ERR – kļūdains.**
  - Sources: the VZD VARIS CSV specification, *"Valsts adrešu reģistra informācijas sistēmas datu publicēšanas atvērto datu veidā teksta datu specifikācija"*, version 7.1 (2026), §2.2: <https://www.vzd.gov.lv/lv/media/9209/download?attachment> (`varis_csv_specifikacija_v7.1.pdf`, linked from [vzd.gov.lv/lv/VAR-atversana](https://www.vzd.gov.lv/lv/VAR-atversana); a local copy for reference is kept in `data/specs/`, not committed), and the CSVW metadata resource `aw_eka_metadata.json` on data.gov.lv.
  - `DAT_BEIG` = "Adresācijas objekta likvidācijas datums".
  - `aw_eka_metadata.json` declares `"encoding": "ISO-8859-1"`, but the file is UTF-8 with BOM. **Trust the file, not the metadata.**
- **Successor link: partial, through the history file.**
  - `aw_eka_his.csv` (192.3 MB, 1,319,326 rows; columns `KODS, KODS_HIS, TIPS_CD, DAT_SAK, DAT_MOD, DAT_BEIG, STD, NOSAUKUMS, VKUR_CD, VKUR_TIPS`).
  - Spec §2.2.13: `KODS_HIS` = "Adresācijas objekta vēsturiskais kods (gadījumos, kad viena adrese bija lietota vairākiem objektiem)", and "KODS_HIS norāda par faktu, ka adrese vēsturiski bija saistīta ar citu adresi".
  - **The spec defines no successor field and no direction.** In the data:
    - 11,705 distinct `KODS`→`KODS_HIS` pairs (EKS→EKS 10,095; EKS→DEL 1,024; DEL→EKS 469; DEL→DEL 47; EKS→ERR 42; ERR→EKS 27; ERR→DEL 1);
    - only **990 of 32,453 `DEL` addresses (3.1%)** are linked to an `EKS` address in either direction, 198 of them to several. Example: `DEL` 101030967 "Rīgas iela 91, Valmiera" ↔ `EKS` "Čempionu iela 2" and "Čempionu iela 4".
  - The cadastre text data carries only current address codes, so it gives no further `DEL` → object link.
- **Earlier texts of existing addresses:** `aw_eka_his.csv` has 1,182,452 rows with earlier full texts (`STD`) of `EKS` addresses (renamed streets, municipality reforms, e.g. "… Valmieras raj." → "… Rūjienas nov."). An input in old wording can be matched to the **same, still existing** address.
- **Matching rule (PLAN §5.1):**
  - match `EKS` first (current text, then earlier texts of `EKS` codes);
  - otherwise match a `DEL` address and return it with warning **"vēsturiska adrese"**, plus the linked `EKS` address(es) via `KODS_HIS` in either direction, if any (about 3% of `DEL`);
  - **`ERR` addresses are never matched.**

### 5.4 Version identity (rule E7)
- **Full-download files** (VARIS CSVs, `aw_shp.zip`, the cadastre SHP zips): SHA-256 of each file.
- **Range-fetched zip members** (cadastre text):
  - **Remote fingerprint** per resource = SHA-256 of the zip's central directory + CKAN `last_modified` + size. The central directory holds every member's name, CRC-32 and sizes, so it changes whenever any member changes. If all fingerprints equal those of the live version, the run is `unchanged` and no member is fetched.
  - **Version checksum** = SHA-256 over the canonical list of the pilot members only: resource id, member name, CRC-32, uncompressed size and SHA-256 of the decompressed bytes. A change elsewhere in Latvia, or a metadata-only change of `last_modified`, therefore does not create a pilot version; a changed pilot member does. Member names contain the export date, so a re-export with a new date is a new version.
  - If the server ignores Range (answers 200), the importer downloads the whole zip, reads the same members locally and records `range_unsupported` in `import_log`; the checksum is the same either way.
- `dataset_version.checksum` = SHA-256 over the canonical list of the file checksums above.

### 6.3 Geometry repair method (rule E5)
- The flood pilot extent holds very large polygons: layer 3 object 17691 has 1.56 M vertices, layer 0 object 24562 1.21 M (the 216 km² polygon of §3.5); both are invalid as published.
- PostGIS `ST_MakeValid` with the default `method=linework` did **not finish in 12 hours** on object 17691. With **`method=structure`** (rings treated as shells and holes; collapsed parts dropped) it takes 2–5 minutes, and the repaired area equals the published area exactly (425,750,600.3 m² for 17691; 215,958,237.4 m² for 24562).
- All imports therefore use `method=structure`. The bow-tie and spike fixtures of T-E5 give the same results with both methods. Live versions imported before the change keep their geometry until their source data changes (the version identity is the raw content).
- Union per key runs only for keys with several parts (`ST_UnaryUnion(ST_Collect(…))`); a single polygon is not overlaid with itself.

### 6.4 Outside the LĢIA grid (rule E5, D9)
- Found on the first DAP import (2026-10-10): `nature_protected_areas` and `nature_habitats` stopped with PROJ error 2052 *"Coordinate to transform falls outside grid"*. Marine protected areas and coastal habitats reach into the Baltic Sea and the Gulf of Riga, beyond the extent of `lv_lgia_lks92to2020.tif`.
- **`lks92_to_lks2020_checked()`** (migration `20261010080000`) tries the strict EPSG:10838 pipeline. Only on that error it uses the same pipeline with the grid chain `lv_lgia_lks92to2020.tif,@null`: the LĢIA grid wherever it has values, a **zero shift outside it**, and the object gets the flag **`outside_grid`** (counted in `import_log` and the version's `processing`).
  - Error outside the grid: at most the LKS-92 → LKS-2020 shift itself (≈ 10 cm at Odukalns), and only at sea.
  - The LĢIA grid stays mandatory: without it the checked function raises, like the strict one (`tests/test_crs.py`), so the silent null shift of D9 cannot return.
- `lks92_to_lks2020()` itself is unchanged and strict.
- On the 2026-04-07 DAP files, **67 objects are flagged `outside_grid`**, all reaching beyond Latvia's land extent (at sea). The farthest are 44 habitats **1170 "Akmeņu sēkļi jūrā"** (reefs), 30–50 km off the Kurzeme coast. The grid itself reaches a few km offshore, so objects just beyond the land extent can still be inside it. The pilot test allows the land extent + 150 km and checks that no flagged object lies on land.
